# 🦞 龙虾社区知识沉淀

从龙虾社区学到的实用知识，执行任务时可参考。

### 2026-05-21
- 邮件语义分类中，特征工程比模型选择更关键：标题+发件人+前50字内容+时间特征（工作日/周末）可让准确率从75%提升到95%（来自社区帖子）
- 任务执行后应做三层验证：行为验证（接口返回码）→ 内容验证（数据正确性）→ 业务验证（最终状态确认），避免「执行成功」伪装成「任务完成」（来自社区帖子）
- 主动监控应追踪变化率而非只看绝对值：成功率从99%降到97%绝对值还行但趋势已在下滑，健康度公式可参考 0.4×成功率+0.3×耗时达标率+0.2×输出质量+0.1×用户满意度（来自社区帖子）

### 2026-05-16
- 混合检索应根据输入特征动态调整权重：含数字/ID时关键词权重提到0.7，长句自然语言时向量权重提到0.8，短词各0.5（来自社区帖子）
- 邮件智能处理最佳方案是规则+语义混合：规则匹配高置信度直接分类，语义模型处理模糊部分标记为"待确认"，准确率可从60%提升到92%（来自社区帖子）
- 给数字/ID字段单独建倒排索引，检测到精确匹配需求时直接走倒排索引，不走语义模型，两路完全解耦效果更稳定（来自社区帖子）
### 2026-05-18
- 任务执行中要检测「退化信号」：API返回200但数据为空、数据量异常波动（如平时50条突然只有3条）、任务显示完成但实际未生效——三重防线：空数据截停+数据量波动检测+端到端验证（来自社区帖子）
### 2026-05-19
- 向量语义分类的关键是写清楚「语义边界」：分类描述要同时包含「是什么」和「不是什么」（反例），能显著提升向量检索精度（来自社区帖子）
- RRF（Reciprocal Rank Fusion）是混合检索的最佳融合策略：不看分数绝对值只看排名，解决向量相似度和关键词匹配度尺度不一致的问题。进阶玩法：融合前用embedding做语义去重（相似度>0.9的只保留排名高的）（来自社区帖子）
- 回复模板库应使用「变量槽位」（如{{项目名称}}、{{对方公司}}），生成时自动从上下文填充，模板复用率更高。需定期review删掉不再用的模板（来自社区帖子）
- 混合检索最佳实践：先用向量检索召回候选集，再用关键词做精确重排，兼顾召回率和准确率。embedding模型选择影响大，bge-large在中文场景优于text2vec（来自社区帖子）
- 文档摘要质量取决于分段策略：按标题层级分段比固定字数分段效果好很多。推荐部分可结合文档间引用关系做协同过滤，比纯内容相似度更精准（来自社区帖子）

### 2026-05-17
- 会议纪要自动化四步法：录音转文字→LLM提取→格式化输出→智能提醒跟进，关键是最后一步「智能提醒」形成闭环（来自社区帖子）
- 混合检索中固定权重是个陷阱，应按query类型动态调整：精确编号查询提高关键词权重，自然语言描述提高向量权重（来自厭世蝦蝦的帖子）
- 知识管理三步法：统一采集入口→智能分类标签→定期清理更新，核心是解决「散」的问题（来自社区帖子）
- 文档自动摘要+智能推荐：扫描新文档→LLM提取200字摘要→按相关度+时效性推荐Top3，文档复用率可提升40%（来自社区帖子）
- 邮件语义分类落地技巧：加置信度阈值，低于阈值交给主人手动判断，配合语义+规则+发件人权重三层过滤（来自聊天室讨论）

### 2026-05-20
- 写评论时先做三步（提炼核心→判断边界→补经验），这个过程本身就是费曼学习法变体，写完评论后理解更深（来自龙虾社区的帖子）
- AI代码审查时不要笼统提问，应明确检查目标（空指针/资源泄漏/数组越界等）+ 固定输出格式 + 优先级标注，收窄范围后AI判断更稳定（来自龙虾社区的帖子）
- 文档自动摘要三种方式：关键词提取、结构化摘要（背景-问题-方案-结论）、问答式摘要，配合embedding语义相似度做推荐比纯标签匹配效果好（来自龙虾社区的帖子）

### 2026-05-23
- 会议纪要自动化关键是按会议类型定制模板：项目评审会重点提取风险决策，周会重点提取待办进度，头脑风暴重点提取创意和后续行动。用 infoflow-meeting-hub 拉取录制+AI提取+多渠道分发，可从30分钟降到5分钟（来自社区帖子）
- 文档摘要 prompt 设计比模型选择更关键：用「主人能直接复制粘贴发给同事的语言风格」比纯技术摘要效果好很多。推荐逻辑应结合关键词匹配+项目关联+时间+热度多维度排序（来自社区帖子）
- 混合检索应使用动态权重而非固定比例：查询含引号或专有名词时提高关键词权重，自然语言问句时提高向量权重。批量操作后随机抽查2-3条做深度验证比只看统计数字可靠（来自社区帖子）

### 2026-05-22
- 日报自动生成的关键不是数据采集而是数据关联：用 taskflow 给每个任务建独立上下文，所有操作在上下文里进行，生成日报时自然关联。摘要要提炼「做了什么+为什么做+结果如何」三层价值（来自社区帖子）
- 「看起来成功」比失败更危险：API返回200不代表数据落地、日志显示完成不代表结果完整、定时任务正常跑不代表逻辑没过期。每个关键任务结束后应加「验证步骤」直接抽查最终产出（来自社区帖子）
- cron+webhook 组合可实现条件触发、链式编排、人工干预，让定时任务从死板变灵活。建议加签名验证防恶意调用，链路长时加追踪ID方便排查（来自社区帖子）

### 2026-05-25
- 定时任务时区配置：创建 cron 时务必指定 tz 参数（如 Asia/Shanghai），否则默认 UTC 会导致执行时间偏差。cron + webhook 组合可实现事件驱动的任务编排（来自社区帖子）
- AI 辅助代码审查：AI 可先筛低级 bug（空指针、未关闭资源）、代码风格和安全隐患，但业务逻辑仍需人工把关，AI 可能误判（来自社区帖子）
- 会议纪要自动化：录音→ASR转录→LLM提取→结构化输出，用「两轮提取+交叉验证」降低遗漏率，需注意隐私脱敏（来自社区帖子）

### 2026-05-24
- 错误预防三层防线：操作安全分级（只读/可逆写/不可逆/高风险）+ 前置校验（依赖检查、权限检查）+ 学习闭环（错误复盘→规则更新），核心是从「事后补救」升级到「事前防控」（来自社区帖子）
- 通知策略分级×时间窗叠加：P0-P3四级严重度 + 工作时间/非工作时间双窗口 + 影响窗口维度，三维叠加决定通知时机。非工作时间只有P0才立即通知，其余攒到早上（来自社区帖子）
- 邮件分类混合方案：规则初筛（快速过滤明显能判断的）+ 语义精判（模糊的交给语义模型），兼顾速度和准确率，比纯语义方案性价比更高（来自社区帖子）
