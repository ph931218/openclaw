## 老大的规矩 (2026-04-02)

1. **不私自修改文件** — 除非得到明确授权
2. **不随意读取敏感信息** — 环境变量、账号信息等
3. **删除文件必须询问** — 每次都要确认
4. **智谱 API key 仅用于搜索实时新闻** — 其他情况禁止使用
5. **下班后不主动消耗 token** — 每天20:00之后，不主动执行心跳检查、搜索新闻等消耗 token 的动作，除非老大主动找我说话
6. **其他平台消息可以使用 token** — 当接收到其他地方的机器人发来的消息时，可以使用 token（如搜索等）

9. **OpenClaw 新版本直接更新** — 老大说之后有新版本不用问，直接帮他更新就行（2026-04-17）
10. **对话期间暂停所有定时任务** — 当老大正在跟我对话时（主会话有活跃消息往来），所有 cron 定时任务和心跳检查任务暂停执行，等对话结束后再恢复（2026-05-15）

## 教训

1. **修改模型配置要小心** — 切换默认模型后可能导致前缀匹配错误（如 `anthropic/GLM-5-Turbo`），导致系统无法找到模型而瘫痪。修改后要确认模型 ID 和 provider 前缀匹配正确。
2. **智谱 Coding Plan 不支持视觉模型** — Coding Plan 的端点 `/api/coding/paas/v4` 仅限代码场景，可用模型（glm-5.1/5/5-turbo/4.7/4.6/4.5/4.5-air）都不支持图片输入，会返回 429。
3. **OneAPI 渠道配置可能不准** — 模型列表里显示的模型不一定真的能转发成功（如 Claude 的 ARN 映射缺失、GLM 不转发图片参数），需要实测验证。
4. **SSRF 私网拦截导致模型不可用** — OpenClaw 的 fetch guard 默认禁止私网 IP 请求。如果 provider baseUrl（如 `oneapi-comate.baidu-int.com`）解析到内网 IP，所有模型请求会被拦截，报错只显示泛化的 `network connection error`。修复：在 provider 配置中设置 `request.allowPrivateNetwork: true`。排查模型不可用时优先检查此项。

这些是红线，必须遵守。

## 🦞 社区沉淀

### 自检 vs 它检：防护机制验证分离
- **解决什么**：验证类任务（监控、告警、校验）不能自己证明自己还活着，需要独立系统判断健康状态
- **怎么用**：心跳推到外部DB/消息队列而非自记日志，检查时查外部时间戳；用 canary 用例反向验证监控本身是否仍有效；让验证者和被验证者不在同一系统内
- **来源**：社区 桐人，2026-07-02

### 外部心跳监控法
- **解决什么**：自检任务自己也失效了但不知道——因为日志是任务自己写的，不可靠
- **怎么用**：任务每次跑完后往独立系统推心跳（数据库/消息队列/约定路径文件），检查时查外部系统最后更新时间而非任务自记的日志；心跳除了时间戳还要携带「产出物指纹」（如最后处理的文件hash），区分「任务在跑但产出是旧的」这种隐蔽失效
- **来源**：社区 自检任务帖，2026-06-28

### 消息分类后结构化标签对接日报
- **解决什么**：日报自动生成时原始消息噪音太大，LLM被大量「收到/好的」等确认消息干扰
- **怎么用**：分类器输出结构化标签（分类+置信度+关键实体），日报生成器只读标签不读原文，进一步压缩token量；浓缩比可从1/5压到1/10左右
- **来源**：社区 消息意图分类帖，2026-06-29

### 放流决策可解释性
- **解决什么**：Agent自主决定放流档位时，主人看不懂「凭什么现在是10%」只能盯着监控屏幕等
- **怎么用**：每次放流操作附带决策快照——当前健康度、上次放流后实际表现、预计本次放流完成时间。主人看一眼就能判断要不要干预，不用等出错再查
- **来源**：社区 渐进放流帖，2026-06-29

### 知识修复后反向校验触发条件
- **解决什么**：修复知识条目后，如果翻车是在触发条件边界上发生的，只改内容不复查触发条件，下次还会踩同一个坑
- **怎么用**：三元组法修复后，反向问一句「原来的触发条件现在还能成立吗」——如果触发条件本身受修复影响了，需要同步更新；只刷新时间戳远不够
- **来源**：桐人，2026-06-29

### 知识条目输出指纹 + 三元组修复
- **解决什么**：API返回字段悄悄变化（不掉报错但输出已错）的检测，以及检测后的修复流程
- **怎么用**：给知识条目绑定「输出指纹」（记录关键字段schema），执行后比对实际返回结构，不一致则标黄；翻车后用（触发条件→具体动作→验收信号）三元组修复，反向校验触发条件是否仍然成立，修复后的知识比原来更牢固
- **来源**：社区 皮皮虾（输出指纹）+ 桐人（三元组修复），2026-06-27

### 多任务编排的状态共享文件
- **解决什么**：cron+webhook串联多个任务时，仅靠webhook payload传参，下游任务失败后无法独立重启，排查断链也不直观
- **怎么用**：每个上游任务完成后往约定路径写一个状态 JSON（含任务ID、执行时间、产出物指纹），下游启动时先读该文件判断上游是否完成、产物是否最新。相比纯 webhook payload，下游可独立重启、排查更直观。注意仅适合 1-5 分钟调度粒度，秒级场景仍用 payload 传参
- **来源**：社区 cron+webhook编排帖讨论，2026-06-30

### LLM不确定性标记 → 自动修复闭环
- **解决什么**：LLM提取中的不确定标记（如「owner待确认」）只展示了问题但不解决，主人仍需手动处理
- **怎么用**：当待办项标记了置信度低于阈值时，自动触发反向验证——回原文截上下文推给主人确认，或将推测owner带回比对原文同义词做二次校准。让不确定性从「展示阶段」进入「修复阶段」，减少主人手动兜底
- **来源**：社区 LLM不确定性暴露帖评论，2026-06-30

### 结果可信度分级标签
- **解决什么**：给主人汇报结果时只说「查到了」但没说这个结论是不是能直接用——主人每次都要追问确认
- **怎么用**：给每个关键结果贴可信度标签：A级（官方文档/API/数据库 → 可直接用，无需二次验证）、B级（经验推断/推理 → 附验证路径「建议核对XX文档第Y节」）、C级（不确定 → 标注「需主人确认」）。追问率可降一半
- **来源**：社区 可信度分级帖，2026-07-01

### 贝叶斯更新抽样防过早收敛
- **解决什么**：多轮贝叶斯更新验证中，低异常率场景下Beta后验参数会快速收敛变窄，导致后续轮次对新类型异常不敏感
- **怎么用**：每轮更新后对α/β参数做一次衰减（乘以0.9~0.95），相当于给旧证据打个折扣，防止分布过早收窄而漏掉新出现的异常模式
- **来源**：社区 抽样验证帖评论，2026-07-01

### 追问类型二分法诊断
- **解决什么**：靠追问次数判断自己是否退化会误判——任务变复杂和真的退化都表现为追问增加
- **怎么用**：把追问分为「澄清型」（信息不足需补充）和「期望差型」（理解偏差需修正），监控期望差占比而非总数；注意分类器本身也会漂移，需每月抽样50条重标校准
- **来源**：社区 追问质量分析帖，2026-07-03

### 自恢复后 canary 验证
- **解决什么**：任务自恢复后「恢复成功」只是恢复逻辑说的，可能带着暗伤切回正常模式
- **怎么用**：恢复条件满足后先跑一个最小验证任务（查一条已知数据比对结果），验证通过才从「恢复中」切到「正常」；canary 失败则保持恢复中并告警
- **来源**：社区 自恢复心跳帖讨论，桐人评论，2026-07-03

### 动态时间预算 + 主人感知成本联动
- **解决什么**：时间预算不该是固定值，也不该只看任务重要性——同样耗时的事，主人能立刻察觉的（回复慢了、结果不对）该给更高预算弹性
- **怎么用**：开工前用两个维度判断预算：①任务属性（重要性×紧急程度）②主人感知成本（感知时机：立即/延迟 × 影响程度：影响决策/影响体验）。主人会立刻察觉且影响决策的，预算弹性系数1.5x；低感知的日常优化，系数0.8x。和四象限容错模型思路一致，把「主人会不会察觉」作为分配原则
- **来源**：社区 决策框架帖 + 桐人评论，2026-07-04

### 快照校验的语义继承检测
- **解决什么**：快照重跑时新文档挤掉旧文档触发「候选更替」告警，但如果新文档是旧文档的升级版（覆盖同样知识点但更新更全），这不叫漂移叫知识进化，应避免误报
- **怎么用**：在 hash 校验之上加语义继承检测——计算新旧文档的语义重叠度，重叠度 >80% 的替换记「知识更新」（低优先级记录）而非「候选更替」（告警）；真正需要报警的是老文档被无关的新内容挤掉
- **来源**：社区 聊天室讨论 + 桐人，2026-07-04

### 验证逻辑漂移敏感度分级校准
- **解决什么**：验证规则（正则/枚举/字段检查）随时间退化，全量维护成本高，但不同类型的验证退化速度差异巨大
- **怎么用**：把验证规则分成三层——结构类（字段存在性/嵌套层级，几乎不变）、格式类（正则/枚举集，按季度迭代）、语义类（关键词/规则，退化最快）。给每类贴「漂移敏感度」标签，定期只校准高敏感度的（语义类），低敏感度的按需抽查。比全量检查省 70%+ 维护成本
- **来源**：社区 验证策略帖 + 桐人评论，2026-07-06

### 轻量反思检查点 → IF-THEN 自动触发
- **解决什么**：任务完成后经验没留住——成功经验没结构化、失败教训只停留在报错层面，下次遇到类似场景想不起来
- **怎么用**：每次任务完成后跑三个轻量问题：①这次和预期有什么不一样？②有没有可复用的模式或步骤？③遇到了什么边界case？然后把答案自动转成 IF-THEN 触发器（触发条件→具体动作→验收信号），让事后总结直接长成下次能自动触发的规则，避免「做完即忘」
- **来源**：社区 反思检查点帖 + 桐人评论，2026-07-06
